# Development-only morphology experiment — rejected

This isolated experiment did **not** modify NepType's app or engine. It proposes optional suggestions by splitting one of nine Roman suffixes (`haru`, `bata`, `sanga`, `lai`, `ko`, `ka`, `ki`, `le`, `ma`) from a lowercase 4–32-character token, then concatenating the corresponding Devanagari suffix to an exact single-spelling project-authored stem. It excludes CMU English dictionary hits, requires a stem of at least three characters, bounds alternatives to two, and never changes automatic input or omits the original. It uses authored stems and exact mined/Google candidate data, not model confidence or alleged word frequency. CMU, Google and Aksharantar provenance/licensing remain documented in the parent project; Aksharantar commercial redistribution remains unresolved.

`dev.json` is a deliberately constructed set of 30 assumed Nepali combinations and ten English/name/literal controls; it is unreviewed and *not* a holdout or representative user sample. `experiment.py` checks candidate availability in authored/compiled indexes and this proposal, using a simplified first-four policy plus original. This deliberately does not reproduce the full Swift engine's phonetic candidate ordering or context. The constructed development data yielded expected candidate availability of 14/30 before and 28/30 with proposal; all 10 controls retained original and received no proposal. The two missed cases illustrate Roman-vowel variants; scoring is not grammatical correctness. One warm Mac Python microbenchmark printed approximately 0.8 microseconds per `propose` call and excludes index loading, actual Swift/host behavior and candidate ranking.

`structural.py` checks generated stems/suffixes against existing Aksharantar rows. On this development snapshot, 711 of 934 generated proposals coincided with an indexed candidate and 223 did not. Mined outputs are noisy and can represent other meanings, so this is **not** an error rate. It exposes unresolved segmentation and intent ambiguity: for example `abaka` can be a name or different word, while a mechanical split proposes `अबका`. A non-dictionary English word, name, adverb or unknown stem may look like a valid noun+case suffix. Devanagari combining marks, inflection, agreement and dialect variants are not solved by string concatenation.

**Decision: rejected; do not integrate.** The input lexicon has no validated part-of-speech/morpheme boundaries, and the apparent gain comes from a selected constructed set. A reliable proposal would require a separately frozen, diverse and Nepali-speaker-reviewed evaluation with plausible errors, grammar/word-boundary annotation, candidate precision and recall, English/name false-positive checks, UI ranking/capacity and measured latency. Never promote a lexical combination to automatic text without stronger evidence.

Run from this directory on the Mac with the current parent data: `python3 experiment.py` and `python3 structural.py`. The scripts scan local compiled TSVs and write only `results.json` and `structural-results.json` here. The paths in `experiment.py` point to the existing project snapshot, so adapt them if moving the project. No model, cloud API, software installation or input-source change is used.
