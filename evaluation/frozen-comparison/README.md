# Frozen synthetic probe v2

`corpus.json` contains 60 synthetic sentences, 12 each in English, Nepali, mixed language, ambiguity and literal categories. It was authored by a separate agent without running Lekha or inspecting engine outputs, and frozen before the proposed development changes were evaluated. The fixture must not be shown to the development agent or used to select or tune the implementation before the final comparison.

This is not an independently sampled user corpus. Its AI author had the project conversation and existing general context, so it is conversation-informed and may overlap prior words or scenarios. The Nepali references have not been reviewed by native speakers; expected spelling, tokenization, punctuation, dialect and Romanization are uncertain. The texts are illustrative and should not be presented as representative accuracy or unbiased evidence. Multiple full-sentence references are included where spacing or punctuation alternatives were judged plausible, but omissions remain possible. Token-level acceptable alternatives do not imply each combination is included as a full-sentence reference.

Annotations are selective and ordered, not a full tokenization; omitted words have no token-level score. `literal` spans should be scored separately for exact preservation. Some punctuation belongs to the sentence but not an annotation. If a literal span is not recognized as an engine token (e.g. emoji or digits), a containment-based check is weaker than verified positional preservation and should be reported as such. Full-sentence exact match should use Unicode canonical equivalence and should not silently normalize spelling or punctuation. The existing phase-2 evaluator requires exhaustive annotations; use a selective ordered evaluator instead.

`generate.py` creates only the static references. It does not invoke the engine. The fixture hash was generated before testing. Evaluate fixed baseline and fixed candidate builds exactly once, retaining the complete per-case outputs and separate category/token denominators. Any subsequent correction or re-labeling turns it into development material; use another independently prepared set for future validation. No input method was installed or activated.

## Frozen comparison (no tuning after inspection)

The fixture and scorer hashes and both implementations were recorded before the run. The proposed English-preservation rule was selected using a separate development corpus; neither its author nor the fixture author inspected the other's data or engine outputs before the comparison. The baseline and candidate rendered every one of these 60 cases identically, so this probe did not exercise the rule and cannot validate or disprove its effect. Given the substantial structural impact on dictionary homographs and no held-out branch coverage, the proposed automatic rule was rejected and reverted.

Strict full-sentence exact matches were identical for baseline and candidate: English 12/12, Nepali 3/12, mixed 4/12, ambiguity 7/12 and literal 11/12. Selectively annotated top-choice tokens were English 103/105, Nepali 94/130, and literal 13/13; expected spellings appeared in the first four contextual choices plus original for 105/105 English and 124/130 Nepali annotations. Some non-tokenized literal spans are checked by output containment, not host position. These cases are AI-authored, conversation-informed, unreviewed and not representative; only selected tokens were annotated. Exact-sentence comparison can penalize valid unlisted spellings or spacing. These numbers are diagnostics, not independent population accuracy.

`baseline-pad.json` and `candidate-pad.json` contain full-sentence and selected-token output. `baseline-session.json` and `candidate-session.json` simulate per-character InputSession use with only previous context and an implicit final boundary; both gave the same exact sentence counts by category in this fixture. This is a core simulation, not native IME events, text ownership, secure-field, undo or device verification. No platform input source was installed.

`pre-evaluation-hashes.txt` records frozen fixture, baseline/candidate source, and evaluators before the run. `pad-evaluator.swift` and `sequential-evaluator.swift` can be compiled as `main.swift` alongside the relevant Swift core files; set the two `LEKHA_*_INDEX` paths and pass `corpus.json`. The pad evaluator scores selected annotations in order; it does not assume unannotated words are English or Nepali.
