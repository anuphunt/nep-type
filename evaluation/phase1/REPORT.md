# Phase 1: offline indexes — experimental candidate layer

## Data and reproducibility

- **English:** Carnegie Mellon University Pronouncing Dictionary (`cmusphinx/cmudict`), commit `74790861f652b15e4ac49015a90074ad62a27690`, `cmudict.dict`, SHA-256 `81917843c7f44ce2b094ac63873c2c7a4cf802040792c455ba3ca406891c3d22`. The pinned source is included at `data/sources/cmudict.dict`; license at `data/sources/CMUDICT-LICENSE.txt` and in each app bundle. Source: https://github.com/cmusphinx/cmudict/tree/74790861f652b15e4ac49015a90074ad62a27690 . Its BSD-style terms permit source and binary redistribution and modification with notice and disclaimer retained in source and binary documentation/materials. It is an American pronunciation dictionary including names and rare forms, not a calibrated frequency list or reliable language detector. Transform: retain lowercase ASCII letter-only word forms, remove numbered pronunciation variants, sort and deduplicate; pronunciations are not included in the derived index. No frequency is claimed.
- **Nepali:** 259 romanized keys extracted without semantic changes from Lekha's existing hand-authored Swift lexicon; now in `data/sources/nepali-authored-v1.json`. These project-authored entries are limited and not an independently sourced corpus. No rights over third-party material are asserted. These curated entries retain first-choice priority. A Google-derived experimental alias index has since been bundled as described below.
- Rebuild with `python3 scripts/build-indexes.py`. It checks the pinned English SHA-256, validates Nepali entries, and produces `Sources/NepaliCore/GeneratedIndexes.swift`. Two runs produced identical SHA-256 `6e9d6f6c30e413d17824f2e7300f66812eac0d31781537be6b3c8c8cb1b371f5`; generated file 997,448 bytes, 117,493 English forms and 259 Nepali keys. Generated data is compiled into the apps; no network is needed at runtime. Unknown words retain existing phonetic fallback and original candidate.

## Third-party Nepali sources reviewed, not bundled

- [AI4Bharat Aksharantar](https://huggingface.co/datasets/ai4bharat/Aksharantar) lists a Nepali training set and labels manually collected data CC-BY and mined/existing sources CC0. Its card also lists multiple sources including Dakshina, Wikidata and sampling methods, and gives a generic CC-BY rather than an explicit version in the displayed licensing section. The pinned Nepali archive and row labels have now been inspected; see the follow-up audit below. The source chain and commercial rights remain unresolved. The user has authorized local project integration and will address commercial licensing before distribution; see the latest follow-up below. A repository MIT license on IndicXlit's code/model does not establish rights for this dataset.
- [Google Dakshina](https://github.com/google-research-datasets/dakshina) says its dataset is CC BY-SA 4.0, which permits commercial use subject to attribution and share-alike for adaptations; exact implications for a product distribution require review. Its listed language set does not include Nepali, so it is not a direct Nepali solution. None was bundled.
- [NepaliTransliteralDataset](https://github.com/SushilShrestha/NepaliTransliteralDataset) describes itself as open source but its repository page provided no explicit data license. Do not bundle without permission or explicit license.
- [wordfreq](https://github.com/rspeer/wordfreq) distinguishes Apache-licensed code and CC BY-SA 4.0 data with additional source attribution requirements. It is not bundled; a product decision about share-alike and downstream attribution would be needed before using it.
- [dwyl/english-words](https://github.com/dwyl/english-words) advertises Unlicense, but its README says copyright in its original list still belongs to another party; upstream rights are unresolved. Not bundled.

This is a source review, not a legal opinion. Before external distribution verify current source records, data-chain rights and notices. No paid data, model or cloud service was acquired.

## Measurement and status

On Apple M4 Max, macOS 26.6.2, Swift 6.4, optimized standalone microbenchmark: lazy first English lookup including index initialization 28.269 ms; 100,000 warm exact lookups p50 0.042 µs, p95 0.084 µs, p99 0.125 µs; 100,000 Nepali `pani` candidate calls mean 3.315 µs. These are one local run, CPU microbenchmarks, not end-to-end keystroke or cold app launch latency. Reproduce by compiling `evaluation/phase1/main.swift` with the two core files; app performance and memory require further tests. English membership is lazily initialized when called.

The original English index remains evidence only; automatic bilingual ranking is Phase 2. The later candidate-layer implementation and updated tests are documented below. The frozen Phase 0 comparison set has already been measured and is not an independent blind test.


## Follow-up: Nepali source and alias investigation

### Aksharantar archive and source rights

Inspected the official archive at dataset revision `e418c1fc928d9f5393af33268472cf20c1891be8`; `nep.zip` SHA-256 `8bdcc5957d701ea36b63c00c713b43bc30902774b70736737d480e77929de92c`. The train JSONL contains **2,391,227 IndicCorp**, 3,539 AK-Freq and 2,648 Wikidata rows; validation has 1,989 IndicCorp, 525 AK-Freq, 279 AK-Uni and 11 Wikidata; test has 2,108 AK-Freq, 817 AK-NEF and 1,176 AK-NEI. These are row source labels, not independent proof of each row's underlying copyright chain.

The [pinned dataset card](https://huggingface.co/datasets/ai4bharat/Aksharantar/blob/e418c1fc928d9f5393af33268472cf20c1891be8/README.md) calls mined data CC0 but explicitly says the authors do not own the underlying text and the CC0 applies to the packaging. The [AI4Bharat IndicCorp page](https://indicnlp.ai4bharat.org/corpora/) describes scraped web text and labels that IndicCorp corpus CC BY-NC 4.0. That page lists 12 languages and does not identify the Nepali archive, so we cannot prove the exact Nepali rows are governed by that specific corpus license; nor does the packaging waiver establish rights over underlying material. This is a material unresolved commercial-rights issue, not a definitive legal conclusion that individual words are protected or that use is forbidden. Source labels alone do not clear it. Obtain authoritative clarification of the exact Nepali source/version and rights or independent legal review before distributing a derived index. **At that audit stage, no Aksharantar data was bundled. The user subsequently requested normal local-build integration; see below.**

Read-only inspection used `inspect_aksharantar.py` against the pinned temporary archive. All IndicCorp training rows passed simple lowercase-ASCII Roman and Devanagari-codepoint checks. These checks do not establish correctness. In a deterministic key-hash sample, 176 of 2,074 sampled Roman keys had multiple native outputs (maximum five). On the earlier small 48-distinct-word baseline, 15 Roman keys appeared in the filtered training rows and nine included an annotated target. This measures pair inclusion only, not accuracy, recall on a representative corpus, candidate ranking, or user intent. The stored `score` is model log probability and was not used as frequency. Results: `aksharantar-inspection.json`.

[Saugatkafley/Nepali-Roman-Transliteration](https://huggingface.co/datasets/Saugatkafley/Nepali-Roman-Transliteration) advertises MIT, but its publicly displayed first rows match Aksharantar's train rows, in order, and it omits the source and score columns. That is strong evidence of overlap, not proof of the provenance of every row. Its MIT label alone is insufficient to clear the original sources. It is not bundled.

### Google phonemic lexicon: candidate for development

[Google language-resources Nepali lexicon](https://github.com/google/language-resources/blob/a90601024f07ab7e96c911243324e0adeb16da96/ne/data/lexicon.tsv), revision `a90601024f07ab7e96c911243324e0adeb16da96`, file SHA-256 `a9f616db4ecc35ecde4e519e1438c5501d8574b3623d43370fb0089a31ea8a83`, contains an explicit **Copyright 2018 Google Inc. / CC BY 4.0** notice in the file header. CC BY 4.0 permits commercial reuse and adaptations subject to attribution, license link, change indication, and the other license terms. Confirm the complete attribution and rights chain at release; this is not legal advice. The file contains 54,178 non-comment rows: 48,581 Devanagari rows with 48,575 distinct exact spellings and 5,597 other-script rows. It describes itself as a pronunciation dictionary: its second column is phonemic transcription, not attested informal Roman keystrokes or frequency.

A bounded, deterministic exploratory conversion of phoneme symbols to informal aliases is in `research_google_aliases.py` and accepts only the pinned hash. It processes 48,472 Devanagari rows, skips 109 rows with unsupported symbols, and emits at most 64 aliases per row (298,844 generated aliases including duplicates). On the same tiny Phase 0 set, 39/48 distinct Nepali Roman inputs matched some generated alias and 36/48 included an annotated intended Devanagari spelling; a tiny deterministic alias-key sample had 4 ambiguous aliases out of 78 sampled. This is a coverage probe, not independent evaluation or a quality guarantee. It does not test rankings, usability, realistic input frequencies or whether generated aliases are natural; unknown characters, cap truncation, pronunciation/spelling mismatch, inherent vowels, long vowels, colloquial spellings, named entities and collisions remain concerns. No model score or row count was interpreted as frequency.

For a production follow-up: pin and include the exact CC BY source and attribution, design and document linguist-reviewed pronunciation-to-alias rules, establish bounded candidate counts, separately preserve and tag the existing authored candidates, avoid automatically replacing text based on a weak alias, and test against a genuinely independent consented word/phrase set. Evaluate naturalness, recall and collision rate by category as well as size, cold startup and lookup latency. This paragraph describes the initial investigation; see the later integration and remaining quality limits below.


## Google candidate integration and evaluation (follow-up)

The project now contains the pinned CC BY 4.0 source as `data/sources/google-ne-lexicon.tsv`, its attribution and modification notice as `data/sources/GOOGLE-NE-ATTRIBUTION.txt`, and its deterministic derived index as `data/compiled/google-ne-aliases.tsv`. Both app bundles include the index and the attribution file under `Contents/Resources`. `python3 scripts/build-google-aliases.py` verifies the source SHA-256 and recreates the data without a network. Source revision, license and chain caveats are described above; the initial Google-only build included no Aksharantar data (see the later integration below).

The generation retains Devanagari spellings and maps phonemic symbols to approximate Roman aliases; combinations are deterministically capped at 64 per spelling, aliases outside 2–35 ASCII letters are omitted, results are deduplicated and sorted lexically. Output has 278,253 aliases and 294,428 pairs; 14,555 keys have multiple spellings, with up to nine for a key. The generated file is 10,618,399 bytes, SHA-256 `87a19947eb60a7ac495b675aae980c94b977598cd11874c7b9b23e5d4b42f159`. Its order is **not frequency, confidence or correctness**. 109 source rows with unsupported phoneme representations were skipped.

Existing curated suggestions and phonetic first choice retain priority. Generated alternatives are lower-confidence, appear after those choices and are marked `·` in the typing pad; the Roman original remains available. A generated alternative never automatically changes the preview. The uninstalled IME can cycle the same candidates but its host-app behavior remains unverified. Missing index data falls back to the original engine.

A separately authored 59-word probe, `alias-holdout-v1.json`, was created without using the generated index results, but after the alias rules were designed; it is synthetic, small, contains provisional annotations and is not speaker-reviewed or representative of real typing. In the raw generated index, 39/59 target spellings appeared within the first three lexically ordered values. With curated and phonetic candidates included, 44/59 expected words were present in the standalone UI's visible candidate row; 18/59 were the first choice. These figures should not be combined as independent samples or treated as a product accuracy claim. In the earlier Phase 0 frozen comparison, visible Nepali target candidates increased from 22/28 to 26/28; all original full sentence outputs and top choices remained unchanged.

Exhaustive binary-search verification matched all 278,253 stored keys to their full values; index generation repeated byte-for-byte. Twelve Swift tests passed. The packaged app passed 18 interaction checks including generated candidate marking, selection and undo, and wrapping. On Apple M4 Max / macOS 26.6.2 with Swift 6.4, five warm-cache app runs from main entry to first window ready took 122.192–136.539 ms. One optimized command-line microbenchmark measured a cold initial mapped lookup of 0.628 ms and 100,000 full candidate lookups p50 14.542 µs, p95 24.084 µs, p99 31.083 µs; maximum resident set was 9,748,480 bytes in that benchmark process. These numbers are not end-to-end keystroke latency or guaranteed on other Macs; OS caches affect timing.

Phase 1 has a usable but experimental broad candidate layer, not a validated comprehensive Nepali dictionary. Natural Roman spellings, transliteration ambiguity, lexical ordering, unsupported phonemes, absent inflections, attribution/release review, speaker-reviewed independent tests, user-agreed quality targets, and security of external data all remain open. No context-aware English/Nepali ranking or system installation was performed.


## Follow-up: Aksharantar in the normal local build

The user explicitly requested integrating this dataset in the normal build and will handle commercial licensing before distribution. This is authorization to use it in the project, not verification that third-party commercial rights are cleared. The unresolved provenance and rights issue above remains a **release blocker to resolve before external distribution**. No public release or system input installation was performed.

The normal local app and uninstalled input-source bundle include `data/compiled/aksharantar-indiccorp-v1.tsv`, a filtered, sorted and deduplicated index from the pinned Aksharantar Nepali **training** archive. The file contains only rows with the exact `IndicCorp` source label. The `aksharantar-indiccorp-v1.manifest.json` and `data/sources/AKSHARANTAR-ATTRIBUTION.txt` record source, revision, archive and output hashes, filtering and the unresolved commercial-rights issue; notices are bundled with both apps. All pairs have the recorded `IndicCorp` source tag; other source tags are excluded rather than conflated. Regenerate with `python3 scripts/build-aksharantar-index.py /path/to/nep.zip`, using the pinned archive hash from the manifest. Outputs use an atomic file replacement. No score, model confidence, duplicate count or alphabetical order is interpreted as frequency or quality.

The resulting index contains 2,171,523 distinct Roman keys and 2,391,227 distinct pairs; 188,305 keys have more than one native form, and the maximum is 17. It occupies 98,652,429 bytes, SHA-256 `a62c90b709c425f78e9b0ffcbb263823e38a3cb3c2f2286d64ecdaaa9b52970d`. Existing first choices and original text remain unchanged. Aksharantar alternatives are ranked after curated/phonetic choices and before Google approximations, sorted lexically within the source, explicitly marked `†` in the candidate row, and require user selection. This source ordering is a product implementation choice, not an estimated probability or Phase 2 contextual ranking. Poor or misleading pairs are possible.

On the previously created 59-word synthetic probe, the visible candidate row included an intended spelling for 45/59 cases, compared with 44/59 before integration; first choice stayed correct for 18/59. This set is small, provisional, not speaker-reviewed, has already been examined, and is not representative. The previous 25-case Phase 0 comparison has exactly the same top outputs and candidate availability; these are not blind results. On the archive's separately labeled 4,101 test rows (2,108 AK-Freq, 817 AK-NEF and 1,176 AK-NEI), **zero Roman keys appeared in this training index**: the exact-match layer alone thus produced zero pairs for that split. This includes an exhaustive index scan and demonstrates inability to generalize there, not an estimate of whole-app accuracy. Test/validation rows were not added to the index; results are in `aksharantar-official-test.json`, with evaluation code in `evaluate-aksharantar.py`.

Thirteen Swift tests passed, including Aksharantar candidate selection, unchanged first choice, original preservation and undo. The native app passed 21 UI smoke checks including the † label and selection. Index generation reproduced the same SHA-256. On Apple M4 Max / macOS 26.6.2 / Swift 6.4: three warm-cache packaged-app runs from main entry to first window ready were 138.730–148.855 ms. In one optimized CLI microbenchmark, first mapped lookup was 0.892 ms, 100,000 full candidate lookups were p50 35.792 µs / p95 47.000 µs / p99 57.291 µs; maximum resident set was 11,239,424 bytes for that benchmark process. This is not a claim about end-to-end typing latency or other devices.

Phase 1 implementation is available for review; user acceptance targets, independent speaker-reviewed quality evaluation and commercial licensing remain open. No Phase 2 contextual ranking was added.
