# New mixed-language diagnostic, 30 October 2026

The 24 newly written synthetic sentences include Nepali-only, English-only and mixed requests; `corpus.json` records one proposed output each. They are not natural user data and no Nepali speaker has reviewed the references. Although initially divided into dev and heldout, both halves were inspected during this task, so neither should be represented as an independent holdout. Variations in Nepali spelling, romanization and intended English borrowings can make multiple outputs valid. This diagnostic checks exact sentences only and is not a language accuracy benchmark.

Before the rule change, 6/12 dev and 5/12 other sentences matched the chosen reference exactly. After the change those exact counts stayed 6/12 and 5/12. The automatically chosen script for `cricket` in the other split changed from `क्रिकेट` to `cricket`; the full sentence still failed because `khelchau` was rendered `खेल्चौ` rather than the proposed `खेल्छौँ`. Other visible errors include `pani` resolving to `पनि` when `पानी` was intended, verb spelling errors such as `pathayo`, and `maile` staying Roman. The feature is not ready for high-confidence automatic conversion.

The rule change is conservative: when a word occurs both in NepType's explicitly common-English set and its authored Nepali lexicon, retain the Roman input by default, mark the decision uncertain and keep the Nepali spelling available. This currently affects the authored English sports loanwords `basketball`, `cricket`, `soccer`, and `volleyball`. It deliberately favors typed English and may require manual selection when the Nepali borrowing is intended; it does not solve ambiguous words in general.

A previously used synthetic mixed fixture retained its earlier 34/34 English tokens, 40/43 Nepali tokens and 17/20 exact sentences after this change. That fixture was already inspected and is not an independent estimate. All 27 Swift tests passed, including the new loanword candidate regression. `before.json`, `after.json`, `mixed-after.json` and `main.swift` are retained for reproducibility. Source indexes are loaded from the main project's `data/compiled` paths as with the existing evaluator. No dataset frequency was inferred from confidence or lexical order.
