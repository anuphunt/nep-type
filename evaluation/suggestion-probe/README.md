# Frozen candidate-recall probe

`corpus.json` contains 80 isolated Roman-token cases: 60 proposed Nepali readings across daily words, people and places, actions, spelling variants and inflections; ten English controls; and ten name controls. Each case has `id`, `category`, `role`, `roman` and an `acceptable` string array. `role` is `nepali` for a proposed Devanagari candidate and `preserve` for an English or name input where the exact Roman original should remain available. Some Nepali entries allow more than one common written form; other meanings and spellings may also be valid.

The fixture author did **not** run NepType, inspect its candidates or see the developer's suggestion-expansion work. Freeze the evaluator and both engine versions before scoring; do not alter the reference cases or tune against their results after the run. Report each category separately, candidate rank and top-k reachability as well as whether exact Roman input remains selectable. For preserve controls, distinguish original availability from automatic top-choice preservation: availability alone does not prove the engine will select the intended language. If spelling/meaning reference errors become apparent after scoring, record them separately and do not silently edit the frozen fixture.

This is AI-authored, synthetic, conversation-informed material, not independent user data, representative population sampling or a validated Nepali benchmark. No native Nepali speaker reviewed these labels. Romanization and words such as names, borrowings and short forms can have different intended readings. It evaluates isolated candidate lists only, not sentence context, automatic language identification, real OS input methods, data loss, performance or product accuracy. Meaningful release decisions require larger speaker-reviewed, independently collected datasets and real typing studies.

The file was generated by `generate.py`, which contains only proposed references and does not import, call or inspect the keyboard engine. Frozen `corpus.json` SHA-256: `3e2402b4064251d4f11e1d81554cd41eb6c279b0fd8345e60a52f78b5942e694`.

## Frozen comparison (no post-inspection tuning)

The candidate implementation, baseline source, fixture and evaluator were hashed before this single comparison. The development and fixture authors did not inspect each other's cases or outputs before the run. This is an AI-authored, conversation-informed, synthetic and unreviewed fixture, not representative user accuracy.

The experimental single-edit `ch`/`chh` suggestion expansion was rejected and reverted: expected Nepali candidate availability in the first four choices plus original remained 47/60, and top-choice matches remained 31/60. All 80 inputs retained their original as a candidate; English top matches were 10/10 and names 8/10, unchanged. Two candidate lists changed, adding competing spellings without improving expected recall. Neither this probe nor the small development set establishes the accuracy or safety of the added variants.

By Nepali category, expected visible-candidate counts were daily 11/12, actions 10/12, inflections 7/12, people/places 10/12 and variant spellings 9/12, identical before and after. `baseline.json` and `candidate.json` contain all outputs. Isolated-token candidate availability is not sentence typing accuracy, context, OS-host behavior or user correction cost. Multiple spellings or name readings may be acceptable beyond the unreviewed references.

`pre-evaluation-hashes.txt` records fixture, evaluator and baseline/candidate source hashes captured before this comparison. `evaluator.swift` is compiled as `main.swift` with the Swift core and the local index environment variables. No input method was installed.
