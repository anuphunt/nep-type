# Mixed-text diagnostic — authored ambiguity

This 30-sentence synthetic fixture was written for this investigation. It includes English, Romanized Nepali, mixed-language sentences, and ambiguous spellings; the expected strings are one author's proposed outputs, are not Nepali-speaker reviewed, and include assumptions about spacing, names and intended meanings. Both 15-sentence portions were inspected, so neither is independent holdout evidence. It is a diagnostic of exact rendering, not an accuracy estimate or a representative population test. Raw inputs and outputs are in `corpus.json`, `before.json` and `after.json`.

The pre-change engine matched 6/15 dev and 7/15 probe strings exactly. Both numbers were unchanged after the change, and no rendered string changed. Examples of observed differences include `pani` preferring पनि where the proposed output intended पानी, `ma` choosing म where the proposed output intended the locative मा, and unhandled verb spelling (`khelchau`). Some proposed strings join particles even when the Roman input has spaces, which the current character-preserving renderer does not do; those count against exact match even if a separate-word spelling would be acceptable. These cases do not establish which wording a user intended.

The change is general and conservative: when a context decision chooses a Nepali word with multiple distinct project-authored spellings, mark it uncertain while retaining its previous preferred text, all alternatives and the original. Strong evidence for the language does not establish which meaning or spelling is intended. The pad shows uncertainty for a selected word; actual IME/mobile presentation varies. No automatic grammatical rewrite is added because simple adjacent-word rules would also misread pronoun `ma` and other common contexts. This change flags ambiguity; it does not improve automatic transliteration accuracy.

The earlier 20-sentence mixed fixture remained 34/34 English tokens, 40/43 Nepali tokens and 17/20 sentences, and 28 Swift tests passed including multi-spelling and single-spelling uncertainty checks. Both previously used fixtures are not independent evaluation.

`timing.json` records 12 separate cold process invocations for each binary rendering this 30-sentence corpus on this Mac with the same local indexes: medians 27.28 ms before and 27.25 ms after; maximum observed 28.83 and 27.43 ms. These small, sequential process-level samples include startup and JSON output and are not per-keystroke or device performance measurements; they cannot establish a speed difference.

To repeat from the project root, compile `main.swift` against `Sources/NepaliCore/Transliterator.swift`, `Composer.swift`, `GeneratedIndexes.swift` and `GeneratedAliasIndex.swift` with Swift, set the `LEKHA_ALIAS_INDEX` and `LEKHA_AKSHARANTAR_INDEX` paths, then invoke the resulting executable with this corpus path. `evaluation/phase2/run.sh` evaluates the older annotated fixture.
