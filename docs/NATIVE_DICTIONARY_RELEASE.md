# Native dictionary installer release

Mac 0.1.3 (build 4) and Windows 0.1.3-preview.1 update the existing released desktop installers with dictionary `roman-nepali-v2-pilot-v1`, ID `77fb2c90cd99ef6687f508c965af49d794a2dfe415281249f3bbf58e7aec32d7`. The base is the published Mac 0.1.2 source, including the previously released Windows typing pad. Those published installers remain unchanged. The PR integration described below now also includes the newer system-keyboard work from main.

Raw dictionary exports and the generated pack are excluded from Git. `scripts/fetch-runtime-dictionary.py` recovers the exact compiled native pack from the already published, content-addressed web artifact. Compressed download, WebAssembly and extracted pack fingerprints are checked separately. Clean checkouts automatically fetch the verified compiled runtime when all three raw alias exports are absent. `NEPTYPE_PACK_ONLY=1` also explicitly permits building without those exports; all present source files, the provenance file and the complete runtime pack remain fingerprint-checked. Two canonical decoded TSV hashes let the exhaustive Rust reader test verify every decoded row without distributing raw TSV sources.

The Windows three-button layout keeps the original Roman token accessible after the new dictionary adds more suggestions. Its first two ranked suggestions remain visible, with the original token occupying the third slot when required. UI staleness and shortcut guards are retained. Native runtime tests cover actual ABI lookup, correction retention, emoji offsets and handle isolation. Installer checks still require installation, loading, Unicode output/copy, candidate selection including original text, English/language modes, draft restoration, reinstall and uninstall.

This is a dictionary draft release, not corpus-wide linguistic approval. The full corpus contains generated aliases; only the 1,000-entry pilot has its completed review overlay (800 approved, 200 held aliases suppressed). Known historical spelling/ranking differences remain. Historical language-quality tests are retained and recorded separately in CI; they are not represented as passing. The installed vehicle phrase is recorded as a quality observation, while the restart fixture uses `namaste gayera` to test persistence independently of that known lexical regression. Mac UI and runtime checks must distinguish these known language changes from actual control or installation failures.

Mac artifacts must retain Developer ID signing, notarization and stapled tickets for both app/input source and DMG. Windows remains an unsigned x64 typing-pad preview, with the experimental TSF service excluded. Source and installer publication, public hash checks and website download updates occur only after platform build/packaging checks. Existing published release assets are retained. No user-installed apps or keyboards are overwritten by verification.

## PR integration and common-word compatibility

PR #5 incorporates main through `6a109b4`, including the updated website, articles, analytics and Windows system-keyboard installer. The next Windows development package is `0.1.4-preview.1`; its CI tests include registration, locked upgrades, rollback and removal. This integration does not replace either published installer or publish a new release.

A separate, versioned compatibility layer restores 265 established Roman forms from the previous small authored vocabulary and two published examples. `ma` renders as `म`, `gaadi` as `गाडी`, and common English words such as `meeting`, `email` and `office` remain literal in Mixed mode. Intentional and typo indexes still come entirely from the new standalone pack. The retired Google and Aksharantar bulk indexes remain removed. The compatibility file has its own SHA-256 in the manifest; the dictionary ID identifies the unchanged pack, while engine code and this preference hash identify the complete runtime behavior. The large corpus remains a generated draft, not fully linguistically approved.

The original Swift parity snapshot remains in `shared/fixtures/swift-baseline.jsonl` as historical evidence. `standalone-baseline.jsonl` freezes the same 2,286 requests against the new candidate lists and compatibility layer; its provenance records all changed case counts. No plain rendering case changes from the historical snapshot. Independent expected-spelling tests, protocol safety tests and published article examples remain correctness checks. Historical candidate-list differences are no longer hidden behind `continue-on-error` in Windows CI.

The failed Netlify preview tried to validate private raw alias exports that are intentionally absent from Git. All build entrypoints now bootstrap the compiled pack through `engine-data.py check`, verify its pinned fingerprints and reject corrupted files or an accidentally incomplete set of raw exports. No raw exports or SQLite database are uploaded by this fix.
