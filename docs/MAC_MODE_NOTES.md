# Experimental macOS input-source mode controls

The uninstalled IMK controller now returns a macOS input-source menu with session-specific checked Nepali and English options and the Option-Z shortcut hint. A menu action uses the IMK command dictionary's current client and preserves a pending word as original before changing mode; if a pending composition exists and no client is supplied, it refuses the change. Menu checkmarks derive from that controller's own session, rather than a global icon or a typing-pad mode.

An explicit menu selection or Option-Z choice is also remembered in memory by the client process bundle identifier, capped to 64 IDs using LRU eviction. No preference file, text, browser URL or host content is retained. Known clients without a saved manual choice start in Nepali; a client with no identifier remains in its own controller session's current mode. If activation arrives with pending composition, the controller does not write it to the activation sender: it suspends its own handling, keeps the original in memory and lets subsequent keys pass through. Menu changes and candidate callbacks are disabled while ownership is unresolved. This deliberately leaves the marked text unresolved and may require the system to discard the controller; it does not guarantee recovery if the old host or process goes away. This depends on the documented `IMKTextInput.bundleIdentifier` method in the installed macOS SDK's `HIToolbox.framework/Headers/IMKInputSession.h`; it is not evidence that all clients return a useful ID.

Local verification: `bash scripts/build-input-source.sh --disable-sandbox` built the uninstalled bundle, and its `--mode-menu-check` reported initial Nepali, English selection, Nepali restoration, missing-client preservation, synthetic app isolation, 64-entry bounded eviction and pending-composition activation blocking all true. This invokes the controller with no real client; it does not verify macOS input-menu routing, per-app activation, the bundle IDs returned by real host applications, marked-text commit, secure fields or Option-Z delivery. The source was not installed or activated. Host-app tests require the previously pending installation approval.

Real-host deactivation, menu-command sender identity and host ownership remain unverified; this test checks the controller guard without a real client and does not prove a host retained its marked text.

Review update: if deactivation arrives with a pending token and no usable client, the session now retains the token and blocks further handling instead of resetting it. Generationless candidate-panel click callbacks are ignored to avoid an old click committing a new token; Tab/Shift-Tab preview remains available. The rebuilt bundle's local check passed `deactivation-preserves=true`. A blocked token may remain unresolved or be lost if its old host disappears, and this test does not establish real host safety.

Ownership update: a marked composition is bound to the original client proxy object, and mismatches pause instead of writing into another proxy. Context is cleared on a proxy change between words. The controller self-check uses synthetic objects; IMK may rewrap a client and proxy identity does not prove document/range ownership. An unresolved mark can still be lost if the old host disappears. Mouse candidate callbacks remain disabled.

Candidate navigation update: Tab/Shift-Tab cycle the visible panel choices, and Backspace restores Roman from a preview. While ownership is blocked, a user-invoked menu command offers to copy the retained Roman token without automatically copying it or displaying it in the menu. Controller self-checks passed; actual IMK key routing, panel, pasteboard command and host ownership remain unverified, and a retained token can be lost if its controller disappears.

Persistence update: the input-source menu offers opt-in persistence for explicit per-app choices. It is off by default, stores only up to 64 SHA-256 client-ID digests and language modes locally, and clears saved entries on opt-out. The identifiers are pseudonymous rather than anonymous. Isolated cross-process reload and opt-out tests passed, along with malformed-data, bounds and concurrent-access checks. Actual host identifiers, menu routing, protected-field behavior and crash durability remain unverified.
