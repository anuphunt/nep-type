# Android Java index lookup diagnostic

The active `SortedCandidateIndex` uses a private 4 KiB per-lookup read window and positional file reads, bounded to its asset segment. The old implementation read one byte with a new buffer and file operation at a time. This is a lookup implementation optimization only: no ranking, index data, candidate order, automatic conversion or input-method behavior was changed. The reader has no shared mutable cache between concurrent lookups. The test suite covers duplicate keys, segment offsets, no-final-newline, 600 generated keys, 4 KiB boundaries, truncated segments, overflowing offsets and corrupted rows. Matching rows reject more than 4,096 bytes, over 64 candidates, empty values, non-Devanagari/non-joiner scalars and values over 60 scalars; this follows the shared Swift contract. A seeded 3,000-key reservoir from the actual Aksharantar index produced byte-identical candidate lists between the old and new Java implementations. This does not establish linguistic accuracy.

On the development Mac with Homebrew JDK 27, one sequential hot-cache test of 2,000 lookups over ten repeated words after 200 warm-ups yielded p50/p95 of **0.4380/0.5552 ms before** and **0.0131/0.0423 ms after**. These are isolated local Java `FileChannel` calls, in sequential runs with an uncleared OS cache. They are not Android device, APK asset, IME end-to-end, cold-disk, battery or tail guarantees. The SDK and Gradle were unavailable; Android service compilation and real-device behavior remain unverified.

`before/` is a historical diagnostic copy, not active code. Compile it and `NepTypeIndexPerf.java` with an installed JDK, then compile the active `app/src/main/java/app/neptype/keyboard/core/SortedCandidateIndex.java` and the same benchmark into separate output directories. Pass the local `app/src/main/assets/aksharantar-indiccorp-v1.tsv` path. `NepTypeIndexCompare.java` emits candidate lists for newline-delimited keys for comparisons. Data licensing and provenance are unchanged; no dataset is included in this diagnostic folder.
