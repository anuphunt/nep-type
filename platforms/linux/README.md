# Lekha Linux IBus experimental adapter

This is a **research prototype, not a safe daily-use keyboard or release**. It defaults to pass-through. Setting `LEKHA_IBUS_CORE_EXECUTABLE` to an absolute target-system `lekha-conformance` executable opts into local preedit and an asynchronous, coalescing worker process. No input source has been installed or registered. The Mac-built executable cannot run on Linux. Configure `LEKHA_ALIAS_INDEX` and `LEKHA_AKSHARANTAR_INDEX` to use the indexes; their source and license provenance is in the main project.

Roman text is the default; a worker computes candidate suggestions off the event thread, Tab cycles the highlighted option in the candidate panel (Shift-Tab cycles backward), Backspace first returns selection to the original, and space or return commits the selected text and passes the boundary key to the host. A new key returns to the original Roman token. Escape, shortcuts, navigation and unsupported keys commit the original before handing control to the host. Focus-in, focus-out, disable, reset and a transition to a protected content purpose now abandon the local token without a host edit, because client ownership is not proven at those callbacks. Only space and Return commit a selected preview. Host-declared password, PIN, URL, email, phone, numeric, terminal and date/time purposes pass through when exposed by IBus. This relies on host declarations and is not a security guarantee. Each candidate request has a generation; results from prior text, focus or secure-field state are ignored. Candidate timeout or process failure leaves the original marked text available; an ordinary boundary can commit it. The user can keep typing without waiting for the worker; pending lookups coalesce to the latest token. The process starts and shuts down off the key/focus thread. The subprocess timeout runs in the worker. The token is capped at 256 ASCII characters.

The experimental IPC bridge uses bounded nonblocking pipe writes and a shared write/read deadline; an unresponsive or malicious child cannot indefinitely block the candidate worker merely by leaving its input pipe full. A local fake-child test fills the pipe and confirms a timeout, and oversized requests are rejected. This does not make the bridge a production ABI or prove real IBus lifecycle behavior.

This architecture does **not** establish a data-loss guarantee: host preedit, commit delivery and focus callbacks have not been tested in an actual IBus session. IBus documents that focus-in can precede the previous focus-out; this prototype avoids committing old text on either callback, reset or a protected-field transition. The old preedit may be lost or remain host-managed; a delayed old focus-out could also abandon a newer token because context identity is not bound. Real preedit recovery and precise context ownership are not guaranteed. Text-service protocol behavior in secure fields, selections, shortcuts, Unicode, undo and other input methods varies by host. A crash before an owned preedit is committed can still lose that preedit. The async bridge is experimental and lacks a production native ABI, resource isolation and proven process lifecycle. Candidate computation is word-local and does not use prior-word context. Results may not arrive before the user presses a boundary; in that case the original is committed. Do not use for sensitive or valuable text.

## Verification

On the development Mac, the following runs mocked-host tests, including a hung child, timeout, late responses after focus changes, stale generations, and a live portable-core request:

```sh
LEKHA_TEST_CORE=/absolute/path/to/lekha-conformance \
LEKHA_ALIAS_INDEX=/absolute/path/to/google-ne-aliases.tsv \
LEKHA_AKSHARANTAR_INDEX=/absolute/path/to/aksharantar-indiccorp-v1.tsv \
python3 -m unittest discover -s tests -v
```

Thirty-six tests passed with the locally built Mac core, including cursor-navigation, packaging and in-flight worker-close regressions. A single 200-key mock-host probe while a child was unresponsive measured handler p50 0.0013 ms, p95 0.0014 ms, max 0.0073 ms and focus close 0.0017 ms on this Mac; these are not Linux, IBus, realistic GUI or percentile guarantees. The test measures the event callback only, not candidate latency, scheduler overhead, host calls or worker cleanup. Actual Linux Swift support, GI/IBus behavior, index startup, CPU, memory and host compatibility are unverified.

`python3 generate_descriptor.py` prints a candidate descriptor without installing it. A future release requires a real IBus desktop, Python/PyGObject and IBus bindings and a tested Linux native core. Validate original preservation and failures, focus and secure-field callbacks, preedit replacement, Unicode, keyboard layouts, key repeat, selection, undo, other IMEs, X11/Wayland and GTK/Qt/browser/terminal clients across the supported distribution matrix before enablement. Licensing and redistribution review remains outstanding before any distribution.


The lookup table uses the documented [IBusLookupTable](https://ibus.github.io/docs/ibus-1.5/IBusLookupTable.html) and [IBusEngine candidate callbacks](https://ibus.github.io/docs/ibus-1.5/IBusEngine.html), but the Python GI bindings and panel behavior have only been mocked on the Mac. The candidate-click callback carries an index without a generation, so mouse clicks are intentionally ignored: a queued click could refer to a replaced table. Use Tab to select a candidate. Real panel ordering and focus integration must be tested before daily use. The checked Mac has no `ibus`, Docker, Podman or QEMU executable on PATH; no Linux runtime or settings were installed.

Candidate responses are bounded to nine printable, non-control strings of at most 256 Unicode scalars. Invalid entries are ignored. This hardens a mock-tested boundary, not a guarantee against host or engine failures. Backspace restoration applies only while the preview remains marked; post-commit host undo is unverified.

## Manual language mode

The experimental IBus language-bar property cycles through `नेपाली` (mixed suggestions), `English` (literal pass-through), and `सबै ने` (All Nepali suggestions) for the current engine instance. A switch is refused while a Roman preedit is active: finish or cancel the word first. Property callbacks do not identify their input context, so the switch itself never commits a potentially stale token into an unverified field. English mode passes keys to the host without starting a composition; Nepali mode resumes the candidate path. The in-memory mode is retained when the same engine instance loses and regains focus, and resets to Nepali when that instance is recreated. It is not persistent and is not scoped per application. It does not install a shortcut or change the system's global input source. Panel availability and property activation are only mock-tested; in some IBus frontends the property may be hidden or displayed differently. With no configured core executable, both modes still pass through.

Per-application preferences are intentionally not implemented: the upstream [IBus focus-in-id documentation](https://github.com/ibus/ibus/blob/main/src/ibusengine.c) describes the object path as an input-context ID and notes that client names can be generic (for example `gnome-shell`, `xim`, or Qt), rather than reliable application identities. Do not use these names as stable app identifiers. A future platform-specific identity design must establish trust and privacy, handle unsupported desktops, and be verified in real IBus hosts before enabling per-app storage. The [IBus property API](https://ibus.github.io/docs/ibus-1.5/IBusProperty.html) and [engine API](https://ibus.github.io/docs/ibus-1.5/IBusEngine.html) describe the proposed language-bar UI; actual Python GI signatures and frontend behavior remain unverified on Linux.

## Candidate labels and failure recovery

The candidate list labels its first entry `Original` and remaining entries `Choice`; the language-property tooltip describes forward and reverse Tab selection, Space/Return acceptance and Backspace restoration. These labels do not claim numeric shortcuts. Their presentation and accessibility in actual IBus panels have not been verified. If launching or contacting the candidate worker fails, the adapter retains the Roman preedit and limits process restart attempts to once per second while the user continues typing. A subsequent lookup after that cooldown can recover; no key callback waits for the retry. Mock tests cover failure, cooldown and recovery; they do not establish host-level delivery safety.

A further local inventory found no IBus, Docker, Podman, QEMU, Multipass, Colima, UTM, Parallels or VirtualBox executable/application in the checked common locations. This is not proof that no remote Linux environment is available. No runtime was installed or input source registered.

## Read-only diagnostics and source preview

`python3 diagnose.py` reports the current OS, Python, IBus command and introspection-binding availability, whether core/index paths are configured and readable, and whether experimental focus switches are set. It neither connects to the daemon nor registers or changes a keyboard. A reported file as available is not a check of its architecture, contents, license or actual host behavior; an unset core means the adapter stays pass-through. On the development Mac, IBus and its Python bindings were unavailable.

`python3 prepare_preview.py /absolute/path/to/new-preview.zip` creates a **local source-only research archive**, with a SHA-256 manifest of allowlisted files and fixed timestamps. It does not contain or build a portable core, dataset, installed descriptor or IBus runtime; it cannot be used as a keyboard by itself. It never overwrites an existing output and rejects linked source files. Its file order and metadata are deterministic in the same environment; byte identity across different compression-library versions is not promised. The included `generate_descriptor.py` generates a path appropriate to the extracted directory at the time it is run, rather than preserving the development machine's path. Generating the archive or descriptor does not register or enable an input source. No external distribution is authorized or implied; the source, indexes and dependencies still need license review before release.

### Focus ownership safety rationale

IBus upstream notes that [focus-in may precede the earlier focus-out](https://github.com/ibus/ibus/blob/main/bus/ibusimpl.c). Because this adapter has no verified per-context owner, it abandons local state and stops its worker on focus-in/out, reset, disable, or a protected-field transition, without calling commit or changing preedit on that unverified recipient. The candidate panel is hidden to avoid exposing the prior client’s words; a late callback is ignored. This prevents the tested old-token cross-client commit but can lose unresolved preedit; it is a fail-closed experimental tradeoff, not a production solution. Real IBus requires reliable context binding, focus ordering, host-managed preedit and recovery tests. Do not use this prototype for important text.

### Experimental focus context identifiers

Setting `LEKHA_IBUS_FOCUS_ID=1` before starting the uninstalled engine requests IBus's construction-time `has-focus-id` property and handles its `focus-in-id` / `focus-out-id` callbacks. The upstream [IBus engine documentation](https://github.com/ibus/ibus/blob/main/src/ibusengine.c) describes the object path as an input-context identifier; it is not a reliable app identity and the client name is not retained. A focus-in abandons any old unverified preedit without writing into the new context. A delayed focus-out for a **different** context is ignored so it does not discard the current token. Until a valid context path arrives, key events pass through. This experimental path is **off by default** and has only mock tests; constructor property naming, callback delivery, compatibility, and actual GI/IBus hosts require Linux validation before enablement.

The focus ID does not tag individual key events or content-type changes. A delayed focus-in, a reused context path, a late focus-out for the same path, and events delivered after host ownership has changed cannot be distinguished here. Old host preedit can remain unresolved or be lost, and hiding a lookup panel does not establish that any host retained the original. Do not treat this option as a data-loss guarantee or use it with important text.

## Optional focus-commit experiment

The underlying IBus API documents a preedit focus mode that asks the input context to commit its visible preedit on focus loss. Setting `LEKHA_IBUS_FOCUS_COMMIT=1` opts into passing that mode with every preedit update, if the runtime exposes the API; otherwise the adapter falls back to its ordinary update. This is **off by default**. The preedit stays Roman even when another candidate is highlighted, so if the IBus client actually honors focus-commit, it would commit the user's original keys instead of the highlighted candidate. Explicit Space/Return still commits the highlighted choice.

This is an experiment, **not evidence of recovery or a safe daily-use guarantee**. No actual IBus, application, focus order, secure field, daemon crash or different toolkit has been tested. Reset, disable, unknown event delivery, client handling and a crash can still leave or lose old preedit; a host might not honor the mode as expected. There is no explicit commit from a focus callback and no cross-client recovery store. Verify against real contexts and secure fields before enabling. The [upstream IBus header](https://github.com/ibus/ibus/blob/main/src/ibusengine.h) documents `ibus_engine_update_preedit_text_with_mode` and `IBUS_ENGINE_PREEDIT_COMMIT`; this prototype's interpretation and host behavior remain unverified. Mock tests verify opt-in and that the preedit stays original, not real IBus commit delivery.

### Candidate response safety

Before presentation, the prototype rejects candidate values containing spaces (including non-breaking spaces), line/paragraph separators, controls, disallowed format characters, malformed surrogate code points, or more than 256 characters. ZWJ and ZWNJ remain allowed. The background bridge rejects an entire response containing more than 256 entries, closes that worker and leaves the original Roman preedit available rather than delivering a large list on the IBus thread. These are conservative single-token limits: legitimate multiword suggestions are intentionally unavailable. The filters and oversized-response fallback are tested with mocks, but they do not verify real IBus text ownership, focus, protected fields or host behavior.


### Review update: stale replies and literal fields

The worker verifies that a core response's Roman token, composing flag and language match the pending request before showing candidates. A delayed or duplicate same-session reply for a different word is rejected; original preedit remains. Host-reported password, PIN, URL, email, phone, digits, number, terminal and date/time purposes use pass-through where the IBus version exposes those enum values. The optional names are checked dynamically; absent newer values do not break older bindings. These are defensive controls, not proof of host identity, secure input, text integrity or privacy. Real IBus GI binding and host declarations remain unverified. The input-purpose definitions are in [IBus upstream `ibustypes.h`](https://github.com/ibus/ibus/blob/main/src/ibustypes.h).

The worker launches the configured core with only the two local index paths and selected locale variables rather than inheriting the whole IBus process environment. This reduces accidental exposure of unrelated environment variables; the explicitly configured executable still receives the current Roman token and must be trusted. Tests check the actual spawned child does not receive a sentinel secret. This does not sandbox or authenticate the executable, and neither the worker nor the IBus process is a proven security boundary.


## All Nepali suggestions

The language property can select All Nepali suggestions, and the off-thread worker requests that mode from the shared portable engine. The original Roman preedit remains the default; use Tab to select an offered candidate before Space or Return. The worker validates the returned mode and token, and generation checks discard results from an earlier mode. Local mock tests, including a live Mac-built portable-core probe, passed. This does not test actual Linux, IBus or any host editor, and automatic conversion is not implemented.
